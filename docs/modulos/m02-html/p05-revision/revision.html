Política de seguridad de contenidos

Construí la política partiendo de default-src 'self' para permitir los recursos del propio sitio. Después agregué las excepciones necesarias para Google Fonts y los mapas de OpenStreetMap. Para los demás recursos mantuve restricciones que evitan cargar contenido externo que el sitio no necesita.

Directivas de la política y por qué están
Directiva Valor Por qué
default-src 'self' Establece como regla general que los recursos deben proceder del propio sitio.
script-src 'self' Permite cargar los archivos JavaScript del sitio, como componentes.js y cita.js, y bloquea los scripts escritos directamente en el HTML.
style-src 'self' https://fonts.googleapis.com Permite cargar las hojas de estilo locales y los estilos externos utilizados por Google Fonts.
font-src https://fonts.gstatic.com Autoriza la carga de las tipografías de Google Fonts utilizadas en el sitio.
img-src 'self' Permite cargar las imágenes y el logotipo almacenados en la carpeta del sitio.
media-src 'self' Permite cargar archivos de audio y video alojados en el propio sitio.
object-src 'self' Permite mostrar documentos, como archivos PDF, procedentes del propio sitio.
frame-src 'self' https://www.openstreetmap.org Permite incrustar páginas del propio sitio y mapas de OpenStreetMap mediante <iframe>.
base-uri 'self' Limita las direcciones base que puede establecer la etiqueta base al propio sitio.
form-action 'self' Restringe el envío de los formularios a direcciones del propio sitio.

Limitación de frame-ancestors

La directiva frame-ancestors no está activa en el sitio porque solo puede configurarse mediante una cabecera HTTP del servidor, no mediante una etiqueta meta. Como GitHub Pages no permite configurar esta cabecera directamente, el sitio no cuenta con esta protección contra el clickjacking. Identificar las protecciones que no están disponibles también forma parte de una revisión de seguridad.

La validación del navegador no protege

En el formulario de solicitud de cita utilicé atributos como required, pattern, min y max para comprobar que los datos tengan el formato esperado. Sin embargo, estas validaciones se realizan en el navegador y pueden modificarse o eliminarse mediante las herramientas de desarrollo. Por eso, no sustituyen la validación que debe realizar un servidor.

Además, el formulario utiliza action="/api/citas", pero GitHub Pages es un servicio de alojamiento estático y no dispone de un servidor que reciba y almacene las solicitudes. Por esta razón, el formulario permite comprobar la validación del navegador, pero no completa el envío de una cita.
